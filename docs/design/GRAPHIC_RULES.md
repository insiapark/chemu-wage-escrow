# 체무 그림 배치 규칙

체무 두 앱(알바생 앱, 사장님 앱) 와이어프레임에 넣는 아이소메트릭 3D 그림의 자리와 크기 기준이다. 그림은 세 단계다. 히어로 200~240px, 카드 속 작은 장면 96px, 목록 행 3D 아이콘 40px. 근거는 토스와 앱인토스가 공개한 원문이고, 모든 원문을 연 날은 2026-11-23이다.

확인 표시
- 원문 확인: 페이지 본문에서 규칙 문장을 직접 읽은 것.
- 원문 일부 확인: 규칙 문장은 본문에 있지만 수치가 본문에 없거나 예시가 이미지인 것.
- 원문 확인 못 함: 공개 원문에서 근거를 찾지 못한 것. 체무 팀 기준으로만 쓴다.

원문은 15단어 안에서만 옮기고 나머지는 요약이다. 예시 그림은 내려받지 않고 원문 페이지에 보이는 구성만 글로 적는다. 예시 그림의 크기 비율은 원문 페이지에 표시된 예시 화면을 눈으로 잰 값이라 화면 폭 기준 5%p 안팎의 오차가 있다. px 환산은 앱인토스 디자인 도구 문서의 작업 폭 375px(G4)을 기준으로 한다. 이 기준에서 히어로 200~240px은 화면 폭의 약 53~64%, 96px은 약 26%, 40px은 약 11%다.

G1·G2·G5·G7·G15는 `UX_WRITING_RULES.md`의 S7·S8·S15·S16·S14와 같은 원문이다.

아래에서 "체무 기존 그림 규칙"은 와이어프레임 기준서의 아이소메트릭 그림 규칙을 말한다. 히어로는 한 메시지 화면(온보딩 단계, 빈 상태, 완료, 경고, 결과)에만 폭 200~260px로 두고, 리스트, 상세, 시트, 다이얼로그, 먹색 카드 안에는 그림을 두지 않으며, 히어로는 alt=""와 aria-hidden="true"로 처리한다. "체무 토큰 색"은 와이어프레임 기준서의 색 토큰 표를 말한다.

## 2. 그래픽 규칙 요약

### 2.1 그림을 쓰는 화면과 쓰지 않는 화면

| 번호 | 규칙 | 출처 | 상태 | 체무에 적용하는 방법 |
|---|---|---|---|---|
| R1 | 그래픽은 장식이 아니라 화면의 뜻을 쉽게 알게 돕는 것이다. 맥락과 맞지 않는 그림은 나쁜 예다. | G1 | 원문 확인 | 그림마다 그 화면 제목과 같은 뜻을 말하는지 본다. 제목과 뜻이 다른 그림은 뺀다(예: 이의 화면의 축하 장면). |
| R2 | 한 화면의 핵심 그래픽은 하나이고 나머지는 보조 그래픽이나 아이콘으로 바꾼다. 비슷한 크기의 그림이 여럿이면 시선이 흩어진다. | G1 | 원문 확인 | 히어로가 있는 화면에는 96px 그림을 두지 않는다. 96px 그림도 한 화면에 하나다. 40px 행 아이콘은 보조 그래픽이라 함께 쓸 수 있다. |
| R3 | 그림 때문에 핵심 정보가 아래로 밀려 불필요한 스크롤이 생기면 안 된다. | G1 | 원문 확인 | 360×640 화면에서 제목, 핵심 금액, 주 버튼이 첫 화면 안에 모두 보여야 한다. 금액과 목록이 함께 있는 정보 화면에는 히어로를 두지 않는다. |
| R4 | 결과 화면은 소개에서 약속한 결과를 보여 주고, 점수나 등급처럼 뜻을 알기 어려운 결과에는 설명을 붙인다. 좋은 예 결과 화면 4개 중 3개(E21, E25, E31)는 그림 없이 숫자 제목과 설명으로 이루어지고, 1개(E27)는 화면 폭 약 20% 그림을 점수 카드 안에 둔다. | G2, G3 | 원문 확인, 그림 크기는 예시 측정값 | 급여 계산, 정산, 주간 합계처럼 금액이 결과인 화면은 금액을 제목에 두고 뜻 한 줄을 붙인다. 그림은 빼거나 96px 이하 사물 하나로 둔다. |
| R5 | 마지막 작업이 끝나면 완료 문구와 다음에 누를 버튼을 함께 보여 준다. 좋은 예 완료 화면 2개(E17, E23)는 모두 체크 아이콘 하나를 제목 위 가운데에 두고, 크기는 화면 폭 약 20~30%다. | G2, G3, G1 | 원문 확인, 그림 크기는 예시 측정값 | 보관 완료, 확정 완료처럼 단순한 완료는 체크 하나 수준(375 기준 약 72~112px)으로 충분하다. 3D 장면을 쓰는 완료 화면은 제목과 다음 버튼이 첫 화면 안에 들어오는지 함께 본다. |
| R6 | 보여 줄 내용이 없으면 왜 비어 있는지 알려 준다. 빈 화면 예시는 문구 전후 비교뿐이고 그림 규칙은 없다. | G2, G3 | 원문 확인, 그림 규칙은 원문 확인 못 함 | 빈 화면은 이유 한 줄과 다음 할 일이 먼저다. 그림 사용 여부는 체무 기존 그림 규칙(한 메시지 화면이면 히어로 가능)을 따른다. |
| R7 | 오류가 아닌 상황에 느낌표 아이콘을, 기다릴 일이 없는 화면에 로딩 애니메이션을 쓰지 않는다. 아직 내지 않은 서류에 체크 아이콘을 단 화면도 나쁜 예로 나온다. | G1 | 원문 확인 | 급여일 안내, 정산 예정, 날짜 알림에 경고 그림(iso_09, ic_caution)을 쓰지 않는다. 끝나지 않은 항목에 ic_check를 쓰지 않는다. |
| R8 | 불쾌감을 주거나 애원하고 호소하는 감정 표현은 다크패턴에 해당한다. | G1 | 원문 확인 | 이의, 입금 실패, 그만둔 알바 정산 화면에 우는 얼굴이나 매달리는 표정을 쓰지 않는다. 잃는 것은 사실 문장으로 말한다. |

## 4. 체무 그림 3단계 판정

### 4.1 히어로 200~240px는 사물 여러 개가 든 장면에만 맞고, 완료와 결과 화면에서는 줄인다

원문과 맞는 점
- 사물 여러 개가 든 장면을 크게 쓰는 것은 정보 밀도 규칙(R12)과 맞는다. 좋은 예의 큰 그림(E4 약 225px, E11 약 218px)과 같은 크기대다.
- 한 메시지 화면에만, 한 화면에 하나만 두는 체무 기존 그림 규칙은 핵심 그래픽 하나 규칙(R2)과 맞는다.
- 그림을 제목 위 한 자리에 두고 alt=""와 aria-hidden="true"로 처리하는 방식은 Result 컴포넌트(R15, R33)와 맞는다.

원문과 다른 점
- 폭 전체 장면(E16)을 빼면 좋은 예의 가장 큰 그림은 약 225px이고, 240px은 그보다 크다.
- 완료 화면 좋은 예는 3D 장면이 아니라 체크 아이콘 하나(약 75~110px)다(E17, E23).
- 결과 화면 좋은 예는 그림이 없거나 작고, 숫자 제목과 뜻 설명이 화면을 이끈다(E21, E25, E27, E31).
- 단순한 그림을 크게 쓰면 나쁜 예(E3)이고, 큰 그림이 핵심 정보를 밀어내도 나쁜 예(E7)다.

바꿀 것
- 히어로 폭은 200~224px(화면 폭 약 53~60%)로 두고, 온보딩 단계, 소개, 빈 화면, 경고처럼 정보가 적은 한 메시지 화면에만 쓴다. 체무 기존 그림 규칙의 상한 260px도 224px로 맞춘다.
- 급여 확정, 정산, 입금처럼 금액이 결과인 화면은 히어로를 빼고 금액을 제목에 둔다. 그림을 남기면 96px 이하 사물 하나(체크, 금고)로 둔다.
- 보관 완료, 확정 완료 같은 단순 완료 화면의 그림은 체크 하나 수준인 72~112px로 줄인다. 등장 모션은 그대로 둔다.
- 360×640에서 제목, 핵심 금액, 주 버튼이 첫 화면 안에 보이는지 캡처로 본다. 넘치면 그림부터 줄인다.
- iso_06 금고처럼 몸체가 검정에 가까운 그림은 중간 명도로 올린다(R29).

### 4.2 카드 속 작은 장면 96px는 크기는 맞고, 장면이 아니라 사물 하나로 바꾼다

원문과 맞는 점
- 96px(화면 폭 약 26%)은 좋은 예의 작은 그림(제목 위 아이콘 약 45~110px, 카드 안 날씨 그림 약 75px)과 같은 범위다.
- 결과 카드 안 위쪽에 작은 그림 하나를 둔 좋은 예(E27)가 있다.
- TDS Top에 제목 위 에셋 자리와 제목 오른쪽 에셋 자리가 있어 작은 그림을 둘 표준 자리가 있다(R16).

원문과 다른 점
- 사물 여러 개가 든 장면을 96px로 줄이면 디테일이 많은 그래픽은 충분히 크게 쓰라는 규칙(R12)과 어긋난다. 좋은 예의 작은 그림은 모두 사물이나 기호 하나다.
- 카드 여러 장에 96px 장면을 하나씩 넣으면 비슷한 크기 그림이 여럿 늘어선 나쁜 예(E5)와 같은 구성이 된다(R2).
- 히어로와 같은 화면에 두면 핵심 그림이 둘이 된다(R2).
- 96px은 TDS 문서에 없는 값이다. 문서에 있는 가까운 값은 ListRow 이미지 높이 56px과 정사각 52px이고, Asset 프리셋 픽셀 값은 원문 확인 못 함이다. TDS는 Card UI를 ListRow로 대신할 수 있다고 안내한다(R17).

바꿀 것
- 이 단계의 이름을 "작은 장면"에서 "작은 사물"로 바꾸고, 96px 자리에는 사물 하나짜리 3D(icon3d 계열이나 장면에서 주인공 사물만 떼어 낸 그림)만 쓴다.
- 한 화면에 하나, 히어로가 없는 화면에서만 쓴다. 카드가 여러 장 이어지는 화면에서는 96px 그림 대신 40px 행 아이콘을 쓴다.
- 자리는 Top 제목 오른쪽, 제목 위, 결과 카드 안 위쪽 가운데 셋 중 하나로 정한다.
- 96px에서 사물 윤곽이 뭉개지는 그림은 이 자리에 쓰지 않는다(R28).

### 4.3 목록 행 3D 아이콘 40px는 TDS 값과 같고, 각도와 처리 방식을 하나로 맞춘다

원문과 맞는 점
- TDS ListRow 3D 이모지 원본 높이 40px과 같은 값이고(R19), 앱인토스 아이콘 크기 24~40px 안이다(R22).
- 왼쪽 영역에 행마다 아이콘 하나를 두는 구성은 좋은 예(E6, E8)와 같다.
- 사물 하나짜리 입체 아이콘은 토스가 아이콘에서 3D를 넓혀 만드는 방식(R26)과 맞다.

원문과 다른 점
- 좋은 예 혜택 행의 아이콘은 화면 폭 약 5%(약 20px)로 보여 40px보다 작다. 40px은 허용 범위의 위 끝이다.
- 토스 아이콘은 기울어진 사물을 오른쪽 45도 한 각도로 맞춘다(R24). 체무 기존 그림 규칙에는 아이콘 시점과 각도 기준이 없다. 아이소메트릭 시점 자체는 원문에 규칙이 없다.
- TDS는 배경 없는 리소스에 배경색을 함께 쓰도록 안내한다(R20). 체무 기준에는 행 아이콘 배경 처리 방식이 정해져 있지 않다.

바꿀 것
- 40px을 상한으로 두고 더 키우지 않는다.
- icon3d 전체를 한 시점, 한 기울기, 체무 토큰 팔레트로 맞추고, 장면 그림 속 같은 사물과 모양을 같게 둔다.
- 행 글자가 뜻을 말하므로 alt=""로 둔다. 한 행에 아이콘을 둘 붙이지 않고, 상태는 오른쪽 글자나 모서리 배지로 나타낸다.
- ic_caution은 실제 오류나 위험이 있는 행에만, ic_check는 끝난 항목에만 쓴다(R7).
- 투명 배경 아이콘은 모든 행을 같은 방식(연한 회색 스쿼클 배경, 또는 배경 없는 원본 모양)으로 통일한다.

| 결과(금액이 결과) | 없음 | 1개 이하. 결과 카드 안이나 Top 오른쪽 | 내역 행에 행마다 1개 |

| 입력 | 없음 | 없음 | 선택지 행에 행마다 1개 |

바텀시트에 대해서는 토스 예시(E9, E10, E19)가 시트 왼쪽 위나 가운데에 화면 폭 약 18~20% 이모지를 둔다. 체무는 기존 그림 규칙(시트에 그림 없음)을 유지하며, 이 기준은 토스 예시보다 엄격하다.

## 5. 원문으로 확인 못 한 것

- TDS Asset 프레임 프리셋(정사각, 직사각, 원, 카드의 S·M·L) 픽셀 값
