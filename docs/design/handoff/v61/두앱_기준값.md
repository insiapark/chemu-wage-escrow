# 두 앱 기준값 (v61 ~ v65)

알바생 앱과 사장님 앱이 같은 부품에 같은 값을 쓰도록 고른 표입니다. 사장님 줄이 v61에서 쓰고, 알바생 줄은 v61 ~ v65를 이 표대로 맞춥니다. 기록 맞춰 보기 웹도 같은 값을 씁니다.

- 두 값이 다른 곳 74곳은 `../../v51/review/fine_baseline.md`(알바생 v38, 사장님 v39)의 "두 앱의 기준값이 다른 속성"과 같은 순서입니다. 지금 값은 알바생 v59, 사장님 v60에서 다시 잰 값이고 74곳 모두 그대로입니다.
- 값 표기는 partaudit와 같습니다. 글자는 `크기/굵기/줄 간격 비율`, 안 여백은 `위 오른쪽 아래 왼쪽`(px).

## 1. 고르는 순서

1. 접근성: 누르는 대상 44px 이상, 글자 4.5:1과 부품 3:1 명암비, 색만으로 알리지 않기(WCAG 1.4.1), 본문 줄 간격 1.5(WCAG 1.4.8)
2. 토큰에 있는 값: `../../v9/tokens.json`과 두 앱 `:root`의 `--space-*`, `--radius-*`, `--type-*`, 색 토큰. 토큰의 쓰임 칸에 적힌 자리가 있으면 그 자리를 따릅니다
3. 토스 TDS 공개 문서 값: `../../v8/BRIEF_v8_v10.md`와 그 근거 `../../v8/DESIGN_SOURCES.md`에 적힌 값
4. 시연 1 ~ 5, 8, 12단계 화면(사장님 01, 09, 28, 39, 알바생 06, 11, 15, 33, 52)에서 더 많이 쓰는 값

이유 칸 앞의 (1) ~ (4)는 이 순서 번호입니다. 앞 번호에서 갈리면 뒤 번호는 보지 않습니다.

## 2. 더한 토큰

토큰은 사장님 앱 `:root`에 먼저 넣었고, 알바생 줄도 같은 이름과 같은 값으로 `:root`에 넣습니다. spaceaudit, typeaudit는 `:root`의 토큰을 허용 값과 기준으로 읽습니다.

| 토큰 | 값 | 더한 판 | 쓰는 곳과 이유 |
|---|---|---|---|
| `--space-tabbar-clear` | `calc(24px + 42px + 1.6rem + var(--space-section))`, 글자 100%에서 115.6px | 사장님 v61 | 탭 첫 화면 스크롤 끝 여백. 떠 있는 탭바(아래 24, 높이 42px + 1.6rem)에 마지막 줄이 가리지 않게 하고 섹션 간격 24를 둠. 글자 크기를 따라 커져야 해서 고정 토큰 값으로 바꿀 수 없음. 알바생 앱은 화면 아래에 붙은 탭바라 같은 이름을 자기 탭바 높이 식으로 둡니다 |
| `--space-safe-bottom` | `34px` | 알바생 앞 판, 사장님 v64 | 시안 틀(393x852) 아래 안전 영역. 아래 버튼 자리 아래 여백(74곳 11, 24, 27, 32, 36, 42, 48줄) |
| `--space-dock-bottom` | `max(var(--space-safe-bottom), env(safe-area-inset-bottom, 0px), 20px)` | 알바생 앞 판, 사장님 v64 | 아래 버튼 자리, 시트 아래 버튼 자리의 아래 여백 |
| `--lh-t1` ~ `--lh-t7` | 아래 3절 | v62 두 앱 | 글자 단계마다 줄 간격 하나. `line-height: normal`은 쓰지 않음 |

## 3. 줄 간격 토큰 (v62)

(1) 본문 단계(t5 ~ t7)는 WCAG 1.4.8의 1.5, 제목 단계(t1 ~ t4)는 접근성 기준이 없고 (2) 토큰도 없어 (3) TDS 글자 표의 줄 높이를 씁니다. 본문 단계 1.5도 TDS 값(25.5/17, 22.5/15, 19.5/13)과 같습니다.

| 토큰 | 글자 | 값 | 글자 100%의 줄 높이 | 쓰는 곳 |
|---|---|---|---|---|
| `--lh-t1` | 30px | `calc(40 / 30)` (1.33) | 40px | 큰 금액 |
| `--lh-t2` | 26px | `calc(35 / 26)` (1.35) | 35px | 큰 제목, 금액 제목 |
| `--lh-t3` | 22px | `calc(31 / 22)` (1.41) | 31px | 화면 제목 |
| `--lh-t4` | 20px | `1.45` | 29px | 시트, 확인 창 제목, 비교 칸 값 |
| `--lh-t5` | 17px | `1.5` | 25.5px | 부제목, 버튼, 상단 바 제목 |
| `--lh-t6` | 15px | `1.5` | 22.5px | 목록 제목, 본문 |
| `--lh-t7` | 13px | `1.5` | 19.5px | 보조 글, 배지, 탭바 글자 |

- 글자 크기를 정하는 모든 규칙에 같은 단계의 줄 간격을 함께 적습니다(`font-size:var(--type-t6);line-height:var(--lh-t6)`). 한 줄짜리 버튼, 배지, 탭바 글자도 같습니다(판단 2).
- 높이가 정해진 작은 상자(알림 수 배지 20px)는 줄 간격 토큰을 쓰고 상자 안에서 가운데 맞춤으로 둡니다.
- 고정폭 숫자(`font-variant-numeric: tabular-nums`)는 금액과 시각을 따로 크게 보여 주는 칸에 둡니다(판단 3): 제목 금액, 카드 금액, 행 오른쪽 금액, 행 보조 줄의 시각과 금액, 시각 칸, 버튼 안 금액.

| 문제 있음 | `danger` | `--bg-critical-weak` / `--fg-critical-on-weak` | 4.93:1 | 안 들어옴 |
| 다음 | 기본 | `--bg-neutral-weak` / `--fg-neutral-secondary` | 7.89:1 | 오늘 밤 근무, 다음 근무 …, 쉬는 날, 근무 없는 날, 남은 주, 아직 안 열어 봄. 상태가 아닌 이름표(남긴 이유, A님이 남긴 이유, A님에게도 보여요, B님 앱, 받는 사람, 보관된 돈은 꺼낼 수 없음, 꺼내는 기능 없음)도 이 색 |

- 바꾸는 배지: 사장님 앱 근무 중(ok → acc), 오늘 밤 근무와 다음 근무 …와 B님 앱(acc → 기본), 입금됨(기본 → ok). 알바생 앱 확정 대기(07, acc → warn), 근무 중(ok → acc), 오늘 밤 근무(acc → 기본), 입금됨(기본 → ok), 지금(warn → acc).
- 사장님 "아직 보관 못 함"(warn)과 알바생 "안 들어옴"(danger)은 같은 사건의 두 쪽 글자입니다. 사장님에게는 할 일(확인 필요), 알바생에게는 받지 못한 돈(문제 있음)이라 색이 다르고 글자도 달라 같은 글자 다른 색이 아닙니다.
- 진행 단계 원의 색은 배지와 따로 둡니다: done과 cur 먹색, ok `--bg-positive-solid`, warn `--bg-warning-weak`와 `--fg-warning-icon`, bad `--bg-critical-solid`와 흰 아이콘(74곳 67줄), next `--bg-neutral-weak`.

## 7. 점검 도구로 잴 때

- partaudit는 목록 행 갈래를 글자 줄 수의 합(제목 줄 + 보조 줄)으로 나눠, 제목 1줄 + 보조 3줄과 제목 2줄 + 보조 2줄이 같은 "4줄"이 됩니다. t6와 t7의 줄 높이(22.5, 19.5)가 달라 두 짜임은 높이가 늘 3px 다릅니다. 행 안에 단추나 입력칸이 있는 행, 오른쪽 고름 표시(.rk) 행도 같은 갈래로 잡힙니다. 그래서 v63에서 사본 `../../v51/_tools/partaudit2.mjs`를 만들어 갈래를 제목 줄, 보조 줄, 행 안 단추와 입력칸으로 나누고 .rk를 앞 표시에서 뺐습니다. 두 도구 결과를 함께 적습니다.
- 기록 맞춰 보기 웹은 PANEL이 없어 세밀 점검 도구가 열지 못합니다. 같은 판정(간격 토큰, 글자 단계, 줄 간격 토큰, 고정폭 숫자)을 상태 다섯 x 폭 둘에 거는 `../../v51/_tools/vfine.mjs`로 잽니다.
