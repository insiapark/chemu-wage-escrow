# 체무 라이팅 가이드

체무 두 앱(알바생 앱, 사장님 앱)의 화면 문구를 쓸 때 한 장으로 보는 가이드다. 규칙 원문과 예외는 `UX_WRITING_RULES.md`(규칙 UX-01~UX-20, 출처 S1~S18), 사건별 문장 틀은 `EVENTS.md`, 자동 검사 규칙은 `ux_rules.json`에 있고, 세 파일은 기준서 `BRIEF_v16_v50.md`와 같은 폴더에 있다. 아래 예문은 해요체로 새로 쓴 체무 문구다.

---

## 1. 체무 말투 다섯 줄

1. 해요체로 쓴다. 회사 잘못으로 생긴 에러에도 해요체다. (UX-01, S7)
2. 소리 내어 읽기 쉬운 말을 쓴다. 업무 한자어와 시스템 말 대신 일상어를 쓴다. (UX-09, UX-10, S1)
3. 돈을 움직인 주어가 보이게 쓴다. 사장님이 확정하고, 체무가 보관하고, 내가 받는다. (UX-02, S7)
4. 탓하거나 겁주지 않는다. 날짜와 할 수 있는 일을 말하고, 반드시, 즉시, 불이익 같은 말을 쓰지 않는다. (UX-04, UX-05, UX-17, S1, S2)
5. 돈이 어디 있는지 먼저 말한다. 문제가 생긴 화면일수록 첫 줄에 돈이 그대로 있다는 사실을 둔다. (UX-15, EVENTS 쓰는 규칙)

## 2. 화면 요소별 규칙

글자 수는 공백을 포함해 센다.

| 요소 | 길이 | 꼴 | 좋은 예 | 근거 |
|---|---|---|---|---|
| 제목 | 20자 안팎, 최대 30자(검사 상한 40자). 글자 200%에서 두 줄 이하 | 지금 상태나 결과를 한 문장으로. 돈이 핵심이면 금액을 넣는다. 메뉴 이름("오늘", "급여")만 쓰지 않는다 | A님 퇴근 기록 2건이 확정을 기다려요 | UX-08, S1 |
| 본문 | 한 문장 45자 안팎, 최대 50자. 카드 2문장, 그 밖의 본문 3문장까지 | 제목에 없는 정보만 쓴다(이유, 돈이 있는 곳, 다음 일). 제목을 되풀이하지 않는다 | 확정하면 체무가 그날 일당을 A님 몫으로 보관해요 | UX-07, UX-08, S1, S5 |
| 주 버튼 | 15자 이하 | 목적어와 "~하기". 한 화면에 채운 주 버튼 하나. 금액, 이름, 날짜, 계산식은 버튼 위 문장으로 올린다 | 버튼 위 "어제 근무 2건, 185,760원" / [2건 확정하기] | UX-11, UX-13, UX-14, S6, S7 |
| 보조 버튼 | 15자 이하 | 물러날 때는 대화창 "닫기", 권하는 시트 "다음에". 다른 행동이면 "~하기" 글자 버튼. "취소", "예", "아니요", "확인" 단독은 쓰지 않는다 | [다음에] [알림 켜기] | UX-11, UX-12, S6, S7 |
| 확인 창 | 제목 한 줄 20자 이하, 본문 한 줄 | 제목은 "~할까요?". 버튼은 [닫기]와 행동 버튼. 되돌릴 수 없으면 그 사실을 한 줄 남긴다. 뒤 화면의 문장을 되풀이하지 않고 그림을 넣지 않는다 | 11월 14일을 결근으로 남길까요? / 남긴 뒤에는 바꿀 수 없어요 / [닫기] [결근으로 남기기] | UX-03, UX-07, UX-12, S7 |
| 토스트 | 한 줄 | 방금 끝난 일의 결과만. 3초, 버튼이 있으면 5초 보인다. 이유와 해결이 필요한 내용은 화면이나 대화창으로 보낸다 | 초대 링크를 복사했어요 | UX-16, S2, S12 |
| 알림 | 한두 문장, 문장마다 50자 이하 | 받는 쪽 기준 사건 표 알림 틀 그대로. 누가 무엇을 했는지와 금액 | 사장님이 11월 21일 근무를 확정했어요. 92,880원을 보관했어요 | UX-20, S3, S6 |
| 에러 | 제목 한 줄, 본문 2문장, 해결 버튼 하나 | 제목은 일어난 일을 쓰는 사람의 말로. 본문은 이유와 돈이 있는 곳. 버튼은 해결 행동. 같은 종류의 에러는 같은 틀 | 근무 확정을 보내지 못했어요 / 인터넷이 끊겨서 보내지 못했어요. 채워 둔 돈은 그대로 있어요 / [다시 확정하기] | UX-10, UX-15, S2, S3 |
| 빈 화면 | 제목 한 줄, 본문 1문장, 버튼 하나 | 왜 비었는지와 언제 채워지는지. 다음에 할 일을 버튼으로 | 보관된 돈이 아직 없어요 / 사장님이 첫 근무를 확정하면 여기에 쌓여요 / [근무 달력 보기] | UX-18, S8 |
| 화면 읽기 이름 | 보이는 글자와 같은 길이 | 보이는 말과 같은 말, 같은 순서. 금액은 "92,880원"(₩ 기호를 쓰지 않는다), 날짜와 시각은 화면 표기 그대로, 배지와 상태는 말로. 그림은 읽지 않게 숨긴다 | 달력 칸 이름 "11월 14일 토요일, 보관됨, 92,880원" | UX-20, S1 |

## 3. 용어집 요약

두 앱이 같은 대상을 같은 말로 부른다. 알바생 쪽과 사장님 쪽에서 짝을 정한 말은 짝 그대로 쓴다. (UX-20, 용어집 전문은 `UX_WRITING_RULES.md` 5절)

| 통일어 | 쓰지 않는 말 |
|---|---|
| 보관된 돈 (상태 "보관됨") | 예치금, 예금토큰, 토큰, 보관한 돈 |
| 채워 둔 돈 (행동 "채우기", "꺼내기") | 넣어 둔 돈, 잔액 |
| 확정, 확정 대기 | 확정 전, 미확정 |
| 확정 요청 | 확인 요청 |
| 고친 기록, 고치기 | 수정, 변경 |
| 고쳐 달라고 요청하기 | 수정 요청 |
| 다르다고 알리기 (상태 "다르다고 알림") | 이의, 이의 제기 |
| 받을 곳 (선택지 "디지털 원화로 받기"는 처음 나올 때 한 줄 풀이) | 지갑, 계좌 정보, 스테이블코인 |
| 들어와요(알바생) / 나가요(사장님) | 지급, 이체 |
| 안 들어온 돈(알바생) / 아직 보관 못 한 돈(사장님) | 체불, 미지급 |
| 일당, 월급(알바생), 인건비(사장님) | 임금(최저임금, 임금대장 같은 법정 이름 빼고) |
| 급여명세서 | 임금명세서 |
| 쉬는 시간 | 휴게, 휴게 시간 |
| 차이 나는 돈 | 차액 |
| 기록 맞춰 보기 | 기록 대조 |
| 결근으로 남기기 | 결근 처리 |
| 알바생, 사장님, A님 | 근로자, 고용주, 사업주 |
| 출근할 수 있는 거리 (값 "가게에서 30m 안") | 출퇴근 인정 범위, 위치 추적 |

## 4. 사건 표 요약

자주 쓰는 사건 8개의 화면 제목이다. {이름}, {날짜}, {금액}, {시각}만 데이터로 채우고, 본문 첫 줄은 제목을 되풀이하지 않고 돈이 어디 있는지나 다음 일을 말한다. (UX-20, 전체 17개는 `EVENTS.md`)

| 번호 | 사건 | 알바생 앱 제목 | 사장님 앱 제목 |
|---|---|---|---|
| E01 | 퇴근 뒤 확정을 기다림 | 사장님 확정을 기다리고 있어요 | {이름}님 {날짜} 근무를 확정해 주세요 |
| E03 | 근무를 확정하고 일당을 보관함 | 사장님이 {날짜} 일당 {금액}을 보관했어요 | {이름}님 일당 {금액}을 보관했어요 |
| E04 | 시간을 고쳐서 확정함 | 사장님이 퇴근 시간을 {시각}으로 고쳤어요 | {이름}님 퇴근 시간을 {시각}으로 고쳤어요 |
| E05 | 기록이 다르다고 알림 | 사장님에게 {항목}이 다르다고 알렸어요 | {이름}님이 {항목}이 다르다고 알렸어요 (날짜는 본문 첫 줄) |
| E08 | 채워 둔 돈이 모자라 보관을 못 함 | {날짜} 일당 {금액}이 아직 안 들어왔어요 | {금액}만 더 채우면 돼요 |
| E10 | 급여일에 월급이 들어감 | 월급 {금액}이 들어왔어요 | {이름}님 월급 {금액}이 나갔어요 |
| E11 | 급여일 입금이 안 됨 | 월급이 아직 안 들어왔어요 (본문 첫 줄 "{금액}은 그대로 보관돼 있어요") | {이름}님 월급이 아직 안 나갔어요 |
| E12 | 그만두고 정산함 | 정산 {금액}을 받았어요 | {이름}님 정산 {금액}이 나갔어요 |

- E08 사장님 쪽은 탓하지 않는다. "모자라요", "못 했어요"까지만 쓴다.
- E11은 원인을 알기 전에는 받을 곳을 의심하게 하지 않는다. 받을 곳 확인은 원인이 받을 곳일 때 그 화면에서만 요청한다.

## 5. 숫자 표기

두 앱이 같은 표기를 쓴다. 토스 공개 글에 숫자 규칙은 없고, 소리 내어 읽기 쉬운 말(S1)과 화면 읽기에서 ₩를 기호로 읽는 문제를 근거로 한 팀 기준이다.

| 대상 | 쓰는 꼴 | 쓰지 않는 꼴 |
|---|---|---|
| 금액 | 92,880원 (세 자리마다 쉼표, 숫자 뒤 "원") | ₩92,880, 92880원 |
| 0원 | 0원 | ₩0, 없음 |
| 덜 받는 돈 | 내 기록보다 30분, 5,160원 덜 받아요 | −5,160원 |
| 날짜 | 11월 14일 토요일 | 11월 14일 (토), 11/14 |
| 시각 | 오후 10:00, 자정은 오전 0:00 | 밤 10시, 22:00 |
| 범위 | 앞뒤를 띄운 "~": 오후 10:00 ~ 오전 8:00, 11월 18일 ~ 20일 | 대시, 붙여 쓴 ~ |
| 남은 날 | 19일 남음 | D-19 |
| 바뀐 값 | 오전 8:00에서 오전 7:30으로 | 오전 8:00 → 7:30 |
| 계산식 | 10시간 − 쉬는 시간 1시간 = 9시간 × 10,320원 = 92,880원 (빼기는 수학 기호 "−" 하나) | 하이픈 빼기, 기호 섞어 쓰기 |
| 버림 | 1원보다 작은 돈은 버린다. 계산식 옆에 "1원보다 작은 돈은 버려요"를 한 번 쓴다. 예: 10,321원 × 3.6시간 = 37,155.6원은 37,155원 | 반올림 |

## 6. 쓰기 전 확인 다섯 가지

1. 제목만 읽어도 지금 상태와 돈이 어디 있는지 알 수 있는가. (UX-08, UX-18)
2. 돈이 움직이는 문장에 주어(사장님, 체무, 나)가 보이는가. (UX-02)
3. 버튼만 읽어도 누른 뒤 일어날 일을 알 수 있고, 15자 이하 "~하기"인가. (UX-11, UX-14)
4. 겁주는 말(반드시, 즉시, 불이익, 손해)과 시스템 말(토큰, 지갑, 블록체인, 오류 코드)이 없는가. (UX-05, UX-10)
5. 용어집, 사건 표, 숫자 표기를 그대로 따랐는가. (UX-20)

## 7. 검사 도구 돌리기

규칙 폴더에서 `node _tools/textdump.mjs <앱 html 절대 경로> <덤프.json 절대 경로> <화면 수>`로 화면 문구를 뽑고 `node _tools/uxlint.mjs <덤프.json> ux_rules.json <결과.md>`를 돌려 error 0이면 내보내고, warn은 고치거나 남기는 이유를 결과 옆에 적는다.
