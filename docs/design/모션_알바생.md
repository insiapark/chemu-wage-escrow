# 체무 알바생 앱 v14 움직임

알바생 앱 v14은 v13 화면, 숫자, 문구를 그대로 두고 움직임만 정리한 판입니다. 기준은 개편 기준 v11~v15의 v14 절이고, 값과 이름은 사장님 앱(`모션_사장님.md`)과 같습니다. 완료 순간에만 짧게 움직이고, 320ms 안에 끝나며, 반복하지 않고, 움직임 줄이기에서는 모두 꺼집니다.

## 움직임 표

모든 값은 `:root`의 토큰(`--motion-*`, `--ease-out`)으로 씁니다. 가속도 곡선은 v3부터 화면 전환에 쓰던 `cubic-bezier(.2,.8,.2,1)`(빠르게 시작해 부드럽게 멈춤) 하나입니다.

| 이름 | 무엇이 | 시간 | 가속도 곡선 | 쓰는 화면 |
|---|---|---|---|---|
| 떠오름 (rise) | 3D 그림이 아래 8px에서 제자리로, 투명에서 보이게 | 320ms (`--motion-rise`) | cubic-bezier(.2,.8,.2,1) | 15 퇴근, 일당 보관, 26 이의 결과: 받아들여짐, 33 급여일 자동 입금(열 때), 47 안 들어온 돈이 보관됨, 69 정산 요청 뒤 |
| 체크 그리기 (draw) | 단계 원 안 체크 선이 처음부터 끝까지 그려짐 | 240ms, 80ms 뒤 시작해 320ms에 끝 (`--motion-draw`, `--motion-draw-delay`) | cubic-bezier(.2,.8,.2,1) | 15 "사장님 확정" 단계, 26 "사장님이 받아들임" 단계, 33 방금 끝난 입금 단계(단계마다 한 번) |
| 토스트 | 하단 버튼이나 탭바 바로 위에서 8px 아래부터 올라오며 나타남 | 200ms (`--motion-toast`) | cubic-bezier(.2,.8,.2,1) | 버튼을 누른 뒤 토스트가 뜨는 모든 화면 (출근 기록, 이의 보냄, 계약 요청, 알림 보냄, 정산 요청, 받을 곳 고침, 다시 불러옴 등) |
| 바텀시트 | 아래에서 올라옴 | 240ms (`--motion-sheet`, v13 280ms) | cubic-bezier(.2,.8,.2,1) | 19 이의 제기, 31 받을 곳 고르기, 40 사장님께 알리기 전 문자 보기, 46 정산 받기 전 확인 |
| 화면 전환 | 옆으로 밀림 | 300ms (`--motion-screen`, v3 값 유지) | cubic-bezier(.2,.8,.2,1) | 쌓이는 모든 화면, 탭바 숨김 |
| 전체 화면 열기 | 아래에서 올라옴 | 320ms (`--motion-modal`, v3 값 유지) | cubic-bezier(.2,.8,.2,1) | 가입, 출퇴근, 급여일 |
| 탭 바꾸기 | 새 탭 화면이 옅은 상태에서 또렷해짐 | 180ms (v3 값 유지) | ease-out | 탭바로 탭을 바꿀 때 |

완료 순간을 고른 기준은 기준서의 다섯 순간(보관 완료, 확정 완료, 급여일 입금, 정산 완료, 이의 받아들여짐)을 알바생 앱 화면에 맞춘 것입니다. 알바생 앱에서 "보관 완료"와 "확정 완료"는 사장님이 확정하는 순간 함께 오는 15 퇴근, 일당 보관 하나이고, 늦게 보관된 돈이 들어오는 47을 보관 완료에 더했습니다. 정산은 알바생이 요청하는 순간(69)이 이 앱의 완료입니다.

움직이지 않는 것: 금액 숫자(세는 움직임 없음), 실패와 에러 화면(13, 23, 35, 38, 39, 49, 80~82), 빈 상태(05, 25, 55), 기다림(21 퇴근 뒤 확정 대기, 22, 64, 65), 이의 결과: 받아들여지지 않음(27), 목록과 카드, 3D 그림이 있는 안내 화면(00, 01, 11, 12, 20, 32, 43, 45, 53). 21의 시계 원 "pop"(0.6배에서 커지기 350ms)은 완료 순간이 아니라 없앴습니다.

## 지키는 규칙과 구현

| 규칙 | 구현 |
|---|---|
| 완료 순간만 | 전체 화면(15, 33)은 열 때, 쌓이는 화면(26, 47, 69)은 그 상태로 처음 그려질 때만 `.moment`를 붙이고 450ms 뒤 뗍니다. 21에서 사장님이 확정해 15로 바뀌는 순간에도 한 번 붙습니다. 화면을 다시 그리거나 뒤로 돌아와도 되풀이하지 않고, 화면 목록에서 다시 열 때만 다시 한 번 움직입니다 |
| 320ms 안 | 가장 긴 움직임이 320ms(떠오름, 그리고 80ms 뒤 시작하는 240ms 체크 그리기) |
| 무한 반복과 꾸밈 움직임 없음 | `infinite`가 파일에 없습니다. 진행 막대의 1.1초 되풀이 미끄럼과 뼈대의 1.4초 반짝임을 없애고, 막대는 지금 단계만큼 채워 둡니다(급여일 단계마다 25%씩, 계좌 확인 50%). 불러오는 중에는 글자 "근무 기록을 불러오고 있어요"가 role="status"로 읽힙니다 |
| 금액 숫자는 그대로 | 금액에는 움직임을 붙이지 않습니다 |
| 움직임 줄이기 | `prefers-reduced-motion: reduce`이면 CSS에서 모든 transition과 animation을 끄고, 스크립트도 `.moment`와 방금 끝난 단계 표시(`.just`)를 붙이지 않으며 화면 전환 대기 시간을 0으로 둡니다 |
| 캡처는 끝난 모습 | 캡처 주소(`?i=N`)에서는 `.cap`이 모든 움직임을 끄므로 기본 모습이 곧 끝난 모습입니다. 체크 선의 기본값은 다 그려진 상태이고 떠오름의 기본값은 제자리입니다. 급여일(33)은 캡처 주소에서 입금을 마친 상태로 바로 엽니다 |
| 체크 그리기 선 두께 | 체크 경로에 `pathLength="1"`을 주고 그리는 동안만 `vector-effect`를 끕니다. 단계 원 안 아이콘은 24px로 그려지므로 선 두께 1.9px가 그대로입니다 |

## 확인한 것

`motion_test.mjs`(임시 점검 스크립트)로 머리 없는 크롬(480x1200)에서 확인했습니다.

| 점검 | 보통 | 움직임 줄이기(--force-prefers-reduced-motion) |
|---|---|---|
| 15 퇴근, 일당 보관 | rise 320ms(3D), draw 240ms+80ms("사장님 확정"), 450ms 뒤 `.moment` 떼어짐 | 움직임 0개 |
| 퇴근을 누른 뒤 사장님이 확정하는 순간 (21에서 15로) | 퇴근을 누를 때는 움직임 없음, 확정되는 순간 rise 320ms와 draw 240ms+80ms 한 번 | 0개 |
| 26 이의 결과: 받아들여짐 | rise 320ms, draw 240ms+80ms("사장님이 받아들임") | 0개 |
| 47 안 들어온 돈이 보관됨 | rise 320ms | 0개 |
| 69 정산 요청 뒤 (45에서 정산 받기, 시트에서 알리고 정산 받기) | 요청하는 순간 rise 320ms, 그 뒤 다시 그려도 움직임 없음 | 0개 |
| 33 급여일 자동 입금 | 열 때 rise 320ms, 1.2초 뒤부터 1.1초마다 방금 끝난 단계만 draw 240ms+80ms, 450ms 뒤 `.just` 떼어짐 | 0개, `.just` 0개 |
| 35 입금 실패, 49 불러오지 못함, 48 불러오는 중, 21 확정 대기 | 화면 자체 움직임 없음(화면 목록에서 탭을 바꾸며 여는 180ms만) | 0개 |
| 토스트, 시트, 화면 전환, 전체 화면 | 0.2s, 0.24s, 0.3s, 0.32s | 0s |
| 반복(infinite 규칙) | 0개 | 0개 |

## 측정

같은 도구(`scripts/design-audit/audit.mjs`, 창 480x1200)로 v13과 v14 83화면을 쟀습니다.

| 판 | 요약 줄 |
|---|---|
| v13 (전) | screens 83 | small text 0 | low contrast 0 | small targets 0 | screens with >1 filled CTA 0 | radius values 16px 9999px 8px 24px |
| v14 (후) | screens 83 | small text 0 | low contrast 0 | small targets 0 | screens with >1 filled CTA 0 | radius values 16px 9999px 8px 24px |

움직임만 바꿨으므로 다섯 목표가 그대로입니다. 캡처(`cap_worker/`, `_all.jpg`)는 모두 끝난 모습이고, 33 급여일은 입금을 마친 모습으로 찍힙니다. 화면별 결과는 점검 기록에 있습니다.

## 문구 린트

`lint.mjs` 결과(26건)는 v13과 한 줄도 다르지 않습니다. 금지어는 51, 52의 "테스트넷 모의 원화 토큰(KRWt)" 안내 두 곳(v15에서 고침)이고, 버튼 문법 24건은 목록 칸 모양 버튼과 시트나 확인 창을 여는 목록 행(role="button")의 행 전체 글자를 버튼 이름으로 읽은 것입니다(`접근성_점검_알바생.md` 참고). 문구는 바꾸지 않았습니다. 화면 글자 덤프(점검 기록)를 v13과 견주면 33 급여일 하나만 다른데, 캡처 주소에서 입금을 마친 모습으로 열리기 때문입니다.
