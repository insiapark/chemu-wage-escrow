# 체무 사장님 앱 v10 접근성 정리

사장님 앱 v10(`docs/wireframe/owner.html`)은 v9 화면, 숫자, 문구를 그대로 두고 접근성만 마무리한 판입니다. 기준은 `개편기준_v8_v10.md`의 v10 절이고, 출처 태그의 주소는 `디자인_근거.md`에 있습니다.

## 측정 결과

같은 도구(`scripts/design-audit/audit.mjs`, 47화면)를 창 크기 480x1200으로 돌렸습니다. 이 크기에서 휴대폰 맞춤 배율 `fit()`이 1이라(창 안쪽 504x1104, 알림 단추 44px가 44px로 잡힘) 누르는 대상을 CSS 값 그대로 잽니다. v9 보고서의 62건은 440x900에서 약 0.88배로 줄여 잰 값이라 여기서는 다시 쟀습니다.

| 판 | 요약 줄 (480x1200) |
|---|---|
| v9 (전) | screens 47 \| small text 0 \| low contrast 0 \| small targets 11 \| screens with >1 filled CTA 0 \| radius values 16px 9999px 8px 24px |
| v10 (후) | screens 47 \| small text 0 \| low contrast 0 \| small targets 0 \| screens with >1 filled CTA 0 \| radius values 16px 9999px 8px 24px |

v10 목표 다섯 가지(13px 미만 글자 0, 명암비 미달 0, 44px 미만 누르는 대상 0, 채운 버튼이 둘 이상인 화면 0, 모서리 값 8, 16, 24, 9999px)를 모두 맞췄습니다. 측정 도구는 상태 막대를 재지 않습니다.

v9에서 44px에 못 미치던 대상과 v10 값입니다.

| 화면 | 대상 | v9 | v10 |
|---|---|---|---|
| 05 알바생 3명 초대 상태 | 초대 다시 보내기 | 111x36 | 높이 44 |
| 06, 07, 08 오늘 | 섹션 머리 "전체 보기" | 49x28 | 44 이상, 아래 목록과 8px |
| 32 장부 내보내기 | 기간 세그먼트 세 칸 | 110x40 | 높이 44, 칸 사이 8px |
| 39 기록 대조 | 링크 끄기 | 73x36 | 높이 44 |
| 40 아직 보관 못 한 돈 | 채울 금액 입력칸 | 138x25 | 높이 44 |
| 46 그만둔 알바 정산 | 일부만 채우기, 날짜 정하기 | 135x40 | 높이 44 |

## 바꾼 것

| 항목 | 출처 태그 | 체무 v10 |
|---|---|---|
| 누르는 대상 44x44px | HIG-A11y, SEED-Inclusive, WCAG-2.5.5 | 위 표의 대상을 모두 44px 이상으로 키웠습니다. 보이는 아이콘은 24px 그대로이고 단추 상자를 44px(상단 바 아이콘), 52px(시트 닫기)로 둡니다. 버튼, 배지, 입력칸은 고정 높이 대신 최소 높이를 써서 글자가 커지면 같이 커집니다 |
| 대상 사이 8px | Google-Touch, HIG-A11y | 탭바 네 칸 사이 8px, 세그먼트 칸 사이 8px, 하단 버튼 사이 8px, 섹션 머리 "전체 보기"와 아래 목록 사이 8px입니다. 목록 행은 TDS ListRow처럼 서로 붙어 있지만 행마다 높이가 56px 이상이라 누르는 영역이 겹치지 않습니다 |
| 아이콘만 있는 단추 이름 | FF-a11y, TDS-Button | 뒤로 가기, 닫기, 시트 닫기, 알림에 aria-label이 있고, 알림은 "알림, 읽지 않은 알림 1개"처럼 개수를 함께 읽습니다. 모든 아이콘 svg에 aria-hidden="true"를 붙였고(휴대폰 화면 안 이름 없는 아이콘 단추 0개, 가리지 않은 svg 0개), 상태 막대와 홈 표시줄 같은 휴대폰 틀도 aria-hidden입니다 |
| 누르는 행을 키보드로 | FF-a11y | 누르는 목록 행과 안내 상자에 tabindex="0"을 붙였습니다. 다른 화면으로 가는 행과 안내 상자는 role="link"(Enter), 시트나 확인 창을 여는 행은 role="button"(Enter, Space)입니다. 고르는 행(채우는 방법, 채울 금액)은 role="radio"와 aria-checked, 장부에 넣을 내용은 role="checkbox"입니다. 탭바의 지금 탭에는 aria-current="page"를 붙였습니다 |
| 시트, 다이얼로그, 전체 화면 | APG-Dialog, Radix-Dialog, TDS-BottomSheet | 셋 다 role="dialog", aria-modal="true", 보이는 제목에 aria-labelledby로 잇습니다(시트 제목, 다이얼로그 제목, 전체 화면 상단 바 제목이나 온보딩 제목). 열려 있지 않은 층은 inert라서 Tab이 가려진 곳으로 가지 않습니다 |
| 포커스 가둠과 돌려주기 | APG-Dialog, Radix-Dialog | 단추를 눌러 열면 포커스가 층 안 첫 요소로 들어가고(다이얼로그는 가장 안전한 "닫기"로), Tab과 Shift+Tab은 층 안에서만 돌고, Esc나 닫기로 닫으면 연 단추로 돌아갑니다. 연 단추가 다시 그려져 사라졌으면 지금 화면의 첫 요소로 갑니다. 화면 목록에서 바로 연 상태는 연 단추가 없어 포커스를 옮기지 않고, Tab을 누르면 층의 첫 요소로 들어갑니다 |
| 쌓인 다이얼로그 버튼 순서 | APG-Dialog, WCAG22 | 버튼을 세로로 쌓을 때는 확인 버튼을 위에 그리고 DOM 순서도 같게 바꿔, 보이는 순서와 Tab 순서가 같습니다 |
| 글자 크기 전환 | WCAG22 1.4.4, TDS-Type | 오른쪽 화면 목록 패널 위에 "글자 크기 100%, 130%, 200%" 단추를 두었습니다. 휴대폰 안 글자는 v9에서 rem으로 바꿨으므로 뿌리 글자 크기만 바꿉니다. 주소 끝에 `&fs=200`을 붙여도 열립니다 |
| 200%에서 사라지거나 겹치지 않게 | WCAG22 1.4.4, 1.4.10 | 130% 이상에서 하단 버튼과 버튼 줄을 세로로 쌓고, 다이얼로그 버튼도 쌓습니다. 상단 바는 높이를 고정하지 않아 제목이 줄을 바꾸고, 목록 행은 금액이 다음 줄로 내려가며, 먹색 카드는 D-19를 금액 아래로 내립니다. 200%에서 비교 칸과 세그먼트는 한 줄에 하나씩, 두 돈 비교표는 상자 안에서 가로로 스크롤합니다. 알림 숫자 배지는 종 아이콘을 가리지 않게 옆으로 옮깁니다. 긴 낱말은 넘치지 않고 줄을 바꿉니다(overflow-wrap) |
| 움직임 줄이기 | HIG-A11y, SEED-Inclusive | 기기에서 움직임 줄이기를 켜면 화면 전환, 시트, 다이얼로그, 토스트의 움직임을 CSS로 끄고, 스크립트의 화면 전환 대기 시간(300ms)도 0으로 둡니다 |
| 키보드 포커스 표시 | FF-a11y, SEED-Inclusive | 키보드로 옮긴 포커스에만 2px 보라 테두리를 보입니다(:focus-visible) |

## 확인한 동작

`behave.mjs`(임시 점검 스크립트)로 머리 없는 크롬에서 확인했습니다.

| 점검 | 결과 |
|---|---|
| 보관함 채우기 단추로 시트 열기 | 시트 role dialog, 제목 "보관함을 얼마나 채울까요?", 첫 포커스 "닫기", 뒤 화면과 탭바 inert |
| 시트 안 Tab 순환 | 마지막에서 Tab이면 "닫기", 처음에서 Shift+Tab이면 "₩222,912 채우기" |
| 시트 Esc | 닫히고 포커스가 "보관함 채우기"로 돌아옴, 시트 층 inert |
| 시트 바깥 누르기 | 돈이 옮겨지는 시트라 닫히지 않음 |
| 보관된 돈 행으로 다이얼로그 열기 | 첫 포커스 "닫기", 버튼 순서 "채워 둔 돈 꺼내기 / 닫기", Esc로 닫으면 연 행으로 돌아옴 |
| 누르는 행에 Enter | role link인 "12월 10일 급여일 미리 보기" 행에서 급여일 하루 전 화면으로 이동 |
| 확정 완료 전체 화면 | role dialog, aria-modal, 제목 "근무 확정", Esc로 닫으면 aria-hidden과 inert |
| 글자 크기 200% | 뿌리 글자 32px, 탭바 글자 26px, 100%로 돌리면 16px |

## 문구 린트

`lint.mjs owner`의 금지어 지적은 v9와 같이 21, 38의 "테스트넷 모의 원화 토큰(KRWt)" 안내 두 곳뿐입니다. 새로 나온 "버튼 문법" 지적 9건(24의 알바생 몫 행 3개, 33 알바생 초대하기, 38 사업자 계좌, 기록 대조, 고용노동부 상담 1350, 41 일부만 채우기, 43 그 전에 나눠 채워도 돼요)은 문구가 바뀐 것이 아니라, 시트나 확인 창, 전체 화면을 여는 목록 행에 role="button"을 붙이면서 덤프 도구가 행 전체 글자를 버튼 이름으로 읽은 것입니다. 다른 화면으로 가는 행과 안내 상자는 role="link"로 두어 이 지적에서 빠집니다.
