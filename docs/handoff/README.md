# 체무 개발 전달 · 2026-11-28

최준우의 로컬 구현을 팀 리뷰에 넘기기 위한 안내입니다. 실행 방법은 [프론트엔드 README](../../frontend/README.md), 실제 시연 결과는 [검증 증빙](../demo-evidence/2026-11-28/README.md)에 있습니다.

## 구현된 범위

| 구분 | 확인할 수 있는 것 |
|---|---|
| `/` 목데이터 | 계약 수정·동의, 출퇴근, 양측 연습 서명, 보관·지급, 파일 지문 대조 |
| `/sepolia` 실제 연동 | KRWt approve/fund, WorkRecord 양측 서명, confirmAndLock, release, 실제 이벤트와 JSON 대조 |
| 자동 지급 실행기 | 급여 시각까지 대기 후 release 전송. 별도 프로세스와 가스 지불 계정 필요 |
| 복원 | 브라우저 로컬 준비 기록, 서명, 거래 해시, 확정 기록 저장 및 미확인 영수증 재조회 |
| 지갑 호환성 | EOA, 주소 복구와 현재 ERC-1271 검증을 모두 통과하는 EIP-7702 계정 |

컨트랙트 원본과 배포 주소는 다헌님 전달본입니다. 이번 작업은 기존 배포를 사용하며 컨트랙트를 새로 배포하지 않습니다. 실제 모드는 일당 **92,880 KRWt 한 건**입니다.

## 팀원이 실행할 때

저장소 전체를 내려받고 `frontend`에서 실행합니다. `docs/assets`가 실행·빌드 전에 복사되므로 프론트엔드 폴더만 따로 복사하면 안 됩니다.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

macOS/Linux에서는 `npm.cmd` 대신 `npm`을 사용합니다. Node.js 20.9 이상이 필요합니다. 기본 주소는 `http://127.0.0.1:3000`, 실제 연동은 `/sepolia`입니다. Edge가 설치되어 있으면 `npm.cmd run test:e2e`로 브라우저 검증도 실행할 수 있습니다.

목모드는 지갑 없이 실행됩니다. 실제 모드에서 **조회와 파일 검증만 할 때도 지갑이 필요 없습니다.** 서명·거래에는 본인이 제어하는 테스트 지갑을 사용하고, 화면의 두 역할 주소를 확인합니다. 최준우의 테스트 지갑 주소나 공개 연습 계정 주소를 설정하는 것만으로 해당 계정에 서명할 수 있는 것은 아닙니다.

선택 설정은 `frontend/.env.example`을 참고합니다. `.env.local`과 비밀키는 전달 대상에 포함하지 않았습니다. 브라우저의 기존 저장 값이 있으면 환경변수의 초기 역할 주소보다 우선합니다.

## 리뷰할 부분

- `frontend/src/lib/work-record.ts`: 서명 없는 원본 SHA-256, EIP-712 digest, 두 역할의 서명 복구.
- `frontend/src/lib/sepolia-gateway.ts`: 토큰 승인·충전, ERC-1271, nonce·시각·잔액 확인, 거래 영수증과 교체 처리.
- `frontend/src/lib/chain-session.ts`, `frontend/src/components/sepolia-app.tsx`: 새로고침 후 상태 복원, 미확인 거래 중복 전송 방지, 계정 전환 후 동작.
- `frontend/scripts/watch-payday.ts`: 기본 읽기 전용. `--send`와 프로세스의 `RELAYER_PRIVATE_KEY`를 모두 명시해야 전송.
- `frontend/tests`: 금액·상태·서명·영수증 단위 테스트와 브라우저 시나리오.

## 발표 전에 남은 일

1. 코드 리뷰 후 공유 브랜치 게시와 PR 생성. [이슈 초안](issue-draft.md)과 [PR 초안](pr-draft.md)을 준비했습니다. 원격 게시와 팀 메시지 발송은 아직 하지 않았습니다.
2. 팀원이 본인 PC에서 설치·실행하고 동일한 증빙 JSON을 대조합니다.
3. 발표자 PC에서 지갑 계정 전환·새로고침·실행기 대기를 포함해 리허설하고, 네트워크 실패 시 `/` 목모드와 증빙 화면으로 전환합니다.

## 현재 경계와 알려진 제한

- 계약·출퇴근 원본과 서명 준비는 브라우저 localStorage에만 있습니다. 서로 다른 PC에서 계약과 서명을 이어서 처리하려면 공유 API와 인증이 추가로 필요합니다.
- 실제 출퇴근 수집, 은행 원화 입금, 운영 서버, 배포된 상시 실행기는 구현하지 않았습니다. 이번 원본의 근무일은 고정 시연 데이터이며 지급 시각을 앞당긴 테스트입니다.
- 자동 지급은 별도 실행기를 켜 둬야 합니다. 체인 확인 주기와 블록 생성으로 예정 시각과 확인 시각에 차이가 있습니다.
- JSON 검증은 업로드한 파일의 **자기 record ID**와 체인을 대조합니다. 현재 조회 창의 ID 또는 최신 기록과 같다는 뜻은 아닙니다. 과거 정상 파일도 통과합니다. 현재 성공 문구는 이 차이를 상세히 표시하지 않습니다.
- 파일 읽기가 비동기이므로 파일을 바꾼 직후 연속 검증하지 말고 선택 완료 후 실행합니다. 선택 변경·큰 파일 오류 시 이전 읽기 결과를 확실히 지우는 UI 보완은 후속 항목입니다.
- 기록 ID `0xde1f69707a29b791f32aaf9006c09758c22eae46ab4d49341c500a5f7e38cb32`의 92,880 KRWt는 마지막 조회에서 보관 중이었습니다. 추가 지급은 실행하지 않았습니다.
- 이 저장소의 `contracts`는 전달받은 Solidity 원본 보관용입니다. 전체 Hardhat 배포·테스트 환경은 전달본 별도 프로젝트를 사용합니다.

정해진 개발 일정은 기존 [개발 타임라인](../개발_타임라인.md)을 참고합니다. 이 문서는 새 기능 범위를 추가하지 않습니다.
