## 1부. 토스 UX 라이팅 원칙

### 1. 토스의 8가지 라이팅 원칙 [원문 확인]

출처: 토스 테크, 김자유(UX Writer), 2022년 11월 15일. https://toss.tech/article/8-writing-principles-of-toss

| 원칙 이름 | 뜻 (한 줄) |
|---|---|
| Predictable hint | 다음 화면에서 무슨 일이 일어날지 미리 짐작할 수 있게 힌트를 줍니다. |
| Weed cutting | 넣어도 빼도 뜻이 같은 단어(잡초)를 뺍니다. 글자 수가 아니라 의미 없는 단어를 줄이는 것이 목표입니다. |
| Remove empty sentences | 한 화면에서 같은 말을 되풀이하거나 허전해 보여 넣은 문장을 지웁니다. |
| Focus on key message | 사용자가 이미 알거나 지금 필요 없는 설명은 빼고 꼭 볼 내용만 남깁니다. |
| Easy to speak | 말로 잘 쓰지 않는 단어와 업계 전문 용어를 줄이고, 소리 내어 읽어도 자연스럽게 씁니다. |
| Suggest over force | 강요하거나 겁주지 않고, 스스로 고를 수 있다고 느끼게 권합니다. |
| Universal words | 나이, 학력, 업계와 상관없이 누구나 알아듣는 말을 씁니다. 은어와 유행어는 피합니다. |
| Find hidden emotion | 정보 뒤에 있는 감정을 읽고 공감하는 문장을 씁니다. 대출을 다 갚은 사용자에게 축하를 건넨 사례가 나옵니다. |

### 2. 좋은 에러 메시지를 만드는 6가지 원칙 [원문 확인]

출처: 토스 테크, 김자유(UX Writer), 2022년 9월 21일. https://toss.tech/article/21021

| 원칙 | 뜻 (한 줄) |
|---|---|
| 최고의 에러는 발생하지 않는 것 | 문구를 고치기 전에 화면 흐름을 바꿔 에러 자체를 없앨 수 있는지 봅니다. |
| 적절한 컴포넌트 쓰기 | 설명이 길면 다이얼로그를 쓰고, 위급하지 않은 상황에는 빨간색을 쓰지 않습니다. |
| 스스로 해결할 수 있는 방법 알려주기 | 실패 사실만 말하지 않고 해결 방법을 알려 줍니다. 가장 중요한 원칙입니다. |
| 사용자 입장에서 이해할 수 있는 언어로 쓰기 | 시스템 코드나 IT 용어 대신 사용자가 아는 말로 이유와 해결책을 씁니다. |
| 쉽게 해결할 수 있게 도와주기 | 해결까지 드는 수고를 줄입니다. 고객센터 문의를 탭 한 번으로 잇는 버튼을 단 사례가 나옵니다. |
| 부정적인 감정 최소화하기 | 할 수 없는 일보다 할 수 있는 일을 말하고, 강요 대신 권유합니다. "~해야 해요" 대신 "~할 수 있어요"를 예로 듭니다. |

### 3. 버튼과 바텀 시트 규칙 (TDS 컴포넌트 룰) [원문 확인]

출처: 토스피드 UX 라이터 인터뷰. https://toss.im/tossfeed/article/uxwriter-interview

- 바텀 시트 제목은 한 줄로 씁니다.
- 버튼이 하나이고 사용자에게 행동을 요청하면 "~하기"로 씁니다.
- 단순히 다음 화면으로 넘어가는 버튼은 "확인" 또는 "다음"을 씁니다.
- 버튼이 두 개일 때 물러나는 쪽은 "취소" 대신 "닫기" 또는 "다음에"를 씁니다.
- 대출 상환 알림을 "확인해 보세요"에서 상환을 응원하는 말로 바꾸자 지표가 좋아진 사례가 나옵니다.

### 4. 그 밖의 근거

- 해요체: 토스 첫 UX 라이터의 글에서 해요체가 토스의 톤을 만드는 데 가장 큰 역할을 한다고 씁니다. [검색 요약] https://toss.tech/article/1st_uxwriter
- 보이스톤과 잡초 제거기: 디자인 툴에서 토스 보이스톤을 자동으로 적용하는 도구, 반복 쓰는 에러 메시지 템플릿을 컴포넌트처럼 쓰는 장치가 소개됩니다. 세부 규칙은 공개되지 않았습니다. [원문 확인] https://toss.tech/article/toss-people-2

### 5. 체무 앱에 바로 쓸 규칙 15개

| # | 규칙 | 근거 |
|---|---|---|
| 1 | 모든 문장을 해요체로 씁니다. "~습니다", "~하십시오"를 쓰지 않습니다. | 1st_uxwriter [검색 요약] |
| 2 | 한 화면에 메시지는 하나입니다. 제목 한 줄이 그 화면의 전부이고 설명은 한두 줄입니다. 제목과 같은 말을 설명에서 되풀이하지 않습니다. | Remove empty sentences, Focus on key message |
| 3 | 빼도 뜻이 같은 말을 지웁니다. "해당", "진행", "관련", "~하실 수 있습니다", "확인 부탁드립니다", "앞으로", "혹시" 같은 말이 대상입니다. | Weed cutting ("앞으로", "혹시"는 원문에 잡초 예로 나옴) |
| 4 | 버튼 앞 문장이나 버튼 자체로 다음에 무슨 일이 일어나는지 알려 줍니다. 예: "출근하면 오늘 일당 보관이 시작돼요". | Predictable hint |
| 5 | 행동을 요청하는 버튼은 "~하기"로 끝냅니다. "확인" 대신 "출근하기", "일당 보관하기". 아무 일도 일어나지 않고 다음 화면으로만 가는 버튼만 "확인" 또는 "다음"을 씁니다. | TDS 컴포넌트 룰 |
| 6 | 버튼이 두 개면 물러나는 쪽은 "취소" 대신 "닫기" 또는 "다음에"를 씁니다. | TDS 컴포넌트 룰 |
| 7 | 금융·법률 용어를 생활 말로 바꿉니다. "소정근로시간" 대신 "계약한 근무 시간", "예치" 대신 "보관", "지급" 대신 "입금". 락업, 베스팅, 컨트랙트, 토큰은 쓰지 않습니다. | Easy to speak, Universal words, 에러 원칙 4 |
| 8 | 강요하지 않고 권합니다. "~해야 해요" 대신 "~할 수 있어요", 겁주는 말("즉시", "반드시", "불이익") 대신 할 수 있는 일을 씁니다. | Suggest over force, 에러 원칙 6 |
| 9 | 에러에는 해결 방법을 함께 쓰고, 그 해결을 바로 하는 버튼을 답니다. 예: 위치가 멀면 "위치 다시 찾기". | 에러 원칙 3, 5 |
| 10 | 에러 문구를 쓰기 전에 에러를 미리 막을 수 있는지 봅니다. 가게 30m 밖에서는 출근 버튼을 누르기 전부터 거리 안내를 보여 줍니다. | 에러 원칙 1 |
| 11 | 위급하지 않으면 빨간색을 쓰지 않습니다. 위험 #d6383e는 돈이 안 들어온 상황에만, 위치 밖이나 확정 대기는 주의 #c27200 또는 안내 #0f8574를 씁니다. | 에러 원칙 2 |
| 12 | 감정이 큰 순간(급여일 입금, 정산 완료, 이의가 받아들여짐)에는 한 줄 공감을 더합니다. 예: "이번 달도 고생 많으셨어요". | Find hidden emotion |
| 13 | 숫자가 주인공인 화면은 숫자를 제목에 올립니다. 예: "₩92,880 보관했어요". | Focus on key message에서 끌어온 팀 규칙 |
| 14 | 능동형으로 씁니다. "~되었습니다", "~처리됩니다" 대신 "~했어요", "~해요". 주어가 사람(사장님, 나)이면 주어를 드러냅니다. | [원문 미확인] 팀 규칙 |
| 15 | 묻는 문장은 "~하시겠어요?" 대신 "~할까요?"로 짧게 씁니다. | [원문 미확인] 팀 규칙 |

### 2. 3D 일러스트를 어디에 얼마나 크게 두나

| 화면 종류 | 3D 크기 | 자리 | 근거 |
|---|---|---|---|
| 온보딩, 빈 상태, 완료(퇴근 보관, 급여일 입금, 정산 완료), 경고(안 들어온 돈) | 가로 200~260px | 제목 바로 위 히어로. 화면 가운데 정렬 | 토스 "핵심 화면에 3D로 시각적 임팩트"(토스페이스 제작기), 일러스트 팩의 온보딩·빈 상태 권장 |
| 리스트, 표, 상세 | 40~48px 또는 넣지 않음 | 행 왼쪽 아이콘 자리 | 토스 제품 그래픽의 90% 이상이 아이콘(첫 그래픽 디자이너 글) |
| 시트, 다이얼로그 | 넣지 않음 | | 한 화면 한 메시지 원칙과 공간 부족 |
| 로딩 | 넣지 않거나 작은 회전 표시 | 가운데 | 토스는 로딩에 도는 원, 완료에 체크 애니메이션을 씀(모션 글) |

- 한 화면에 3D는 하나만 둡니다.
- 히어로 위아래로 바탕 여백을 둡니다. 히어로 아래 제목까지 24px 이상을 제안합니다. [제안값]
- 움직임을 넣는다면 완료 화면에만 넣습니다. 토스는 앱 안에서 3D 전체 애니메이션 대신 몇 컷의 PNG 시퀀스와 Lottie를 섞어 용량을 줄입니다. [원문 확인]

### 3. 각도, 그림자, 바닥 타일

- 시점 통일: 16개 에셋(iso_00~iso_15)이 모두 같은 시점, 같은 높이에서 바라본 모습이어야 합니다. 토스페이스는 각도가 있는 사물을 모두 오른쪽 45도로 맞췄고, 음식처럼 속을 보여야 하는 것도 같은 높이에서 본 모습으로 통일했습니다. 글자와 함께 쓸 때 시선이 끊기지 않게 하려는 이유입니다. [원문 확인, 2D 이모지 기준]
- 각도 값: 아이소메트릭은 바닥 축을 수평에서 약 30도(픽셀 그림은 가로 2 : 세로 1, 약 26.6도)로 눕히는 것이 일반 관행입니다. 에셋끼리 이 값을 섞지 않습니다. [일반 관행, 토스 근거 없음]
- 광원: 광원은 하나, 왼쪽 위로 고정해 모든 에셋의 밝은 면과 어두운 면 방향을 맞춥니다. [제안값]
- 그림자: 오브젝트 바로 밑의 부드러운 접촉 그림자 하나만 씁니다. 길게 늘어진 투영 그림자는 쓰지 않아 카드 그림자와 방향이 부딪치지 않게 합니다. [제안값]
- 바닥 타일: 오브젝트를 둥근 마름모 타일 위에 앉힙니다. 타일 색은 바탕 #f4f3f0보다 한 단계 어두운 같은 계열 파생값을 쓰고 새 토큰으로 만들지 않습니다. 타일 가장자리는 바탕으로 흐려지게 해 PNG 경계가 보이지 않게 합니다. [제안값]

### 4. 평면 UI와 3D를 섞을 때

- 색: 3D 에셋은 기존 토큰 안의 색만 씁니다. 바탕 계열, 먹색 #19181d, 보라 #5b4bdb가 주색입니다. 토스 첫 그래픽 디자이너는 아이콘에 TDS 색만 써서 UI와 맞췄다고 씁니다. [원문 확인]
- 상태색: 위험 #d6383e, 주의 #c27200, 안내 #0f8574는 그 상태를 말하는 화면의 에셋에만, 한 화면에 한 가지만 씁니다. 위급하지 않은 화면에 빨강을 쓰지 않는 에러 원칙과 같은 기준입니다.
- 놓는 곳: 3D는 바탕 위에만 둡니다. 먹색 카드 안에 넣지 않고, 카드 그림자와 3D 접촉 그림자가 겹치지 않게 카드와 떨어뜨립니다. [팀 규칙]
- 한 팔레트, 두 배경: 토스페이스는 팔레트 하나로 흰 배경과 검은 배경 모두에서 잘 보이게 만들었습니다. 우리 에셋도 바탕 #f4f3f0과 먹색 카드 #19181d 양쪽에서 윤곽이 보이는지 확인합니다. 단, 화면에는 바탕 위에만 둡니다. [원문 확인]
- 형태: 기본 도형과 최소한의 묘사로 만들고, 비율·두께·볼륨을 에셋끼리 맞춥니다. 토스페이스는 손 이모지 약 200개를 한 손에서 만든 것처럼 맞췄습니다. [원문 확인]
- 글자와의 관계: 3D 안에 글자나 숫자를 넣지 않습니다. 숫자는 제목 문구가 맡습니다(1부 규칙 13). [제안값]

### 5. 토스 앱의 3D 이모지·일러스트 사용 방식

- 3D는 핵심 화면과 홍보 그래픽의 키 비주얼에 씁니다. 토스뱅크 모임통장 키 비주얼을 3D 이모지 묶음으로 만들어 앱, 보도자료, SNS에 함께 썼습니다. 앱 안 일반 이모지는 2D 토스페이스로 통일합니다. https://toss.tech/article/22205 (고현선, 2023년 7월 17일) [원문 확인]
- 제품 화면 그래픽의 90% 이상이 아이콘이라 아이콘 세트를 먼저 정비했고, 3D와 애니메이션은 아이콘을 기준으로 키워 만듭니다. 앱을 열자마자 보이거나 한 번에 닿는 화면(홈, 내소비, 전체 탭)을 먼저 고쳤습니다. https://toss.tech/article/1st-graphic-designer (고현선, 2023년 4월 20일) [원문 확인]
- 모션은 감정이 큰 순간(신용점수 상승, 월급날, 생일)의 폭죽, 송금·결제 완료의 체크, 네트워크 끊김 같은 불편한 안내의 가벼운 애니메이션, 카드 발급의 돌려 보는 3D 카드에 씁니다. 앱은 용량 제약이 있어 3D 몇 컷과 Lottie를 섞습니다. https://toss.im/tossfeed/article/why-motion-in-finance (2022년 7월 14일) [원문 확인]
- 그래픽 디자인 팀은 3D가 필요한 키 비주얼과 히어로 그래픽을 주로 만들고, 범용 그래픽은 사내 리소스센터에 모아 제품 디자이너가 씁니다. https://toss.im/tossfeed/article/graphicdesign-team-interview [원문 확인]
- 사내 AI 그래픽 도구 토스트는 2D 그림을 넣으면 토스다운 3D 그래픽을 만들어 줍니다. https://toss.tech/article/ai-graphic-generator-2 [검색 요약]
- 인물 그래픽은 스킨톤 다섯 가지를 정해 섞어 씁니다. https://toss.tech/article/persona [검색 요약]

### 6. 체무 v4 배치 규칙 요약

1. 3D 히어로는 한 화면 한 메시지 화면(온보딩, 빈 상태, 완료, 경고)의 제목 위에만 가로 200~260px로 두고, 한 화면에 하나만 씁니다.
2. 리스트, 표, 상세, 시트에는 3D를 넣지 않거나 40~48px 행 아이콘으로만 씁니다.
3. 16개 에셋은 시점, 각도, 광원 방향을 하나로 맞추고 접촉 그림자 하나만 씁니다.
4. 3D는 바탕 #f4f3f0 위 바닥 타일에 앉히고, 먹색 카드 안에 넣거나 카드 그림자와 겹치지 않게 합니다.
5. 3D 색은 기존 토큰 안에서만 쓰고, 상태색은 그 상태를 말하는 화면에서 한 가지만 씁니다.
