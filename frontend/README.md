# 체무 시연 앱

브라우저 로컬 목데이터 모드와 다헌님의 배포 컨트랙트에 연결하는 Sepolia 모드를 제공합니다. Next.js App Router, React, wagmi, viem을 사용합니다. Scaffold-ETH 2 전체 템플릿이나 Hardhat 프로젝트를 생성한 것은 아닙니다. 기존 저장소의 `frontend/` 구조를 유지했고, 전달받은 ABI와 배포 주소는 `src/contracts/`, Solidity 원본은 저장소의 `contracts/contracts/`에 있습니다. 지갑 UI는 체무 디자인으로 구현하고 IBM Plex Sans KR 글꼴도 로컬 패키지로 제공합니다.

## 실행

Node.js 20.9 이상(권장 22 또는 24)이 필요합니다.

```powershell
cd D:\bay_project\자유주제\chemu-wage-escrow\frontend
npm.cmd ci
npm.cmd run dev
```

브라우저에서 <http://127.0.0.1:3000>을 엽니다. 기본 목데이터 모드는 지갑 없이 시연할 수 있습니다. **실제 테스트넷 연동은 <http://127.0.0.1:3000/sepolia>**에서 실행합니다. 실제 모드는 전달받은 고정 Sepolia 주소와 도메인을 사용하며 `.env.local`이 없어도 공개 RPC로 조회합니다. RPC를 바꾸려면 `.env.example`의 `NEXT_PUBLIC_SEPOLIA_RPC_URL`을 설정합니다. `NEXT_PUBLIC_ESCROW_ADDRESS`와 `NEXT_PUBLIC_CHAIN_ID`는 기존 목모드의 초안 서명 설정에만 사용됩니다.

## 목데이터 시연 순서

1. **사장님 → 근로계약**: 주휴수당 체크를 끈 채 계약을 보냅니다.
2. **알바생 → 근로계약**: 빠진 주휴수당을 확인하고 수정을 요청합니다.
3. **사장님 → 근로계약**: 주휴수당을 포함하고 고친 계약을 보냅니다.
4. **알바생 → 근로계약**: 계약에 동의합니다.
5. **알바생 → 출퇴근**: 출근과 퇴근을 기록하고 연습 서명합니다.
6. **사장님 → 근무 확정**: 동일한 기록에 연습 서명하고 확정합니다. 92,880원이 채워 둔 돈에서 보관된 돈으로 옮겨집니다.
7. **기록 대조**: 현재 기록을 불러오고 검증합니다. JSON의 일당을 고치면 불일치를 확인할 수 있습니다. JSON 파일을 내보내거나 다시 불러올 수도 있습니다.
8. **상단 시연 설정**: 급여일을 20초 뒤로 정하고 앱을 열어 두면 모의 급여가 자동 입금됩니다. 실제 자동 지급 실행기가 아닌 브라우저 타이머입니다.

모바일에서도 상단의 역할 전환과 메뉴를 사용합니다. 초기화는 시연 설정에서 할 수 있습니다. 기존 와이어프레임 1분 시연은 `/reference/wireframe/demo.html`, 독립된 새 기록 대조 진입점은 `/verify`입니다.

## 데이터와 경계

- `src/lib/fixtures.ts`: 2026년 11월 시연 데이터. 마지막 근무는 11월 29일 밤~30일 아침 고정값입니다. GPS도 모의 거리입니다.
- 일당: `(10시간 - 휴게 1시간) × 10,320 = 92,880`.
- 주휴수당: `18 ÷ 40 × 8 × 10,320 = 37,152`.
- 급여: `92,880 × 9일 + 37,152 × 4주 = 984,528`.
- 기존 보관금: `92,880 × 8일 + 37,152 × 4주 = 891,648`. 오늘 일당을 확정하면 984,528입니다. 금액은 수정 전 정상 근무 시나리오이며 979,368원 분기와 이의 처리는 이번 범위에서 제외했습니다.
- `domain.ts`: 계약·출퇴근·보관·입금 상태 전이와 금액 규칙.
- `gateway.ts`: 비동기 목백엔드 인터페이스. 잔액 부족, 중복 확정, 서명 불일치를 검사합니다. 실제 HTTP·컨트랙트 호출은 이 경계에서 교체합니다.
- `store.ts`: `localStorage` 영속화 및 같은 출처의 다른 탭 갱신. 다른 브라우저·기기·사용자 사이에는 공유되지 않습니다. 다중 사용자 서버나 인증 구현이 아닙니다.
- `signatures.ts`: EIP-712 초안 생성 및 서명자 복구. 연습 서명은 공개 Hardhat 개발 계정 2개를 사용합니다. 본인 인증·실제 자금 용도가 아닙니다.
- `verification.ts`: 키를 정렬한 JSON의 SHA-256. 파일의 자체 지문과 별도로 저장한 기준 지문을 함께 대조합니다. 기준 지문도 이 브라우저에 있으므로 온체인 증명은 아닙니다. 다른 브라우저에서는 파일 자체 일치만 표시합니다.
- 모든 거래 ID는 `mock:`으로 시작하며 테스트넷 거래처럼 표시하지 않습니다. 계약·지문도 체인에는 전송하지 않습니다.

## Sepolia 실제 연동 순서

실제 모드는 목데이터 잔액·서명과 분리된 저장 공간을 사용합니다. 월급 누계 984,528원을 체인 잔액인 것처럼 표시하지 않고 **일당 92,880 KRWt 한 건**을 보관·지급합니다. 계약과 출퇴근 원본은 준비된 시연 데이터입니다.

1. `/sepolia`에서 실제 시연용 일반 지갑 두 개의 주소를 지정합니다. 같은 브라우저에서 두 계정을 번갈아 연결해 서명합니다. 새 브라우저의 초기 주소는 `.env.local`의 `NEXT_PUBLIC_DEMO_EMPLOYER`, `NEXT_PUBLIC_DEMO_EMPLOYEE`로 지정할 수 있으며, 생략하면 다헌님이 전달한 시연 주소를 사용합니다. 이미 저장된 브라우저 세션의 주소는 자동 변경하지 않으므로 화면에서 확인합니다. 직접 사용하려면 해당 지갑에 접근할 수 있어야 합니다. 기존 공개 Hardhat 연습 계정은 실제 모드에서 재사용하지 않습니다.
2. 사장님 지갑에 Sepolia ETH와 KRWt가 있는지 확인합니다. KRWt 발행은 토큰 소유자만 할 수 있으므로 필요하면 발행 담당자에게 테스트 토큰을 받습니다.
3. 사장님 계정으로 **토큰 승인하고 충전하기**를 누릅니다. allowance가 부족할 때 `approve(escrow, amount)` 확인 후 `fund(amount)`를 보내고 영수증을 기다립니다. 소수점은 0이라 `92880`을 그대로 사용합니다. v0 컨트랙트에는 가용 보관금 인출 함수가 없습니다.
4. 시연 계약·근무를 확인하고 미래 급여 시각을 정한 뒤 **기록과 급여 시각 확정하기**를 누릅니다. `nextNonce(employer, employee)`와 체인 시각을 조회합니다. 서명·거래 시간을 위해 10분 정도 여유를 둡니다.
5. 알바생 계정, 사장님 계정으로 각각 같은 `WorkRecord`에 서명합니다. 일반 EOA와 MetaMask의 EIP-7702 위임 계정을 지원합니다. 먼저 ECDSA 서명자가 해당 역할의 주소와 일치하는지 검사하고, 주소에 코드가 있으면 ERC-1271 `isValidSignature`도 보관 컨트랙트를 호출자로 지정해 확인합니다. 보관 직전에도 다시 검증합니다. 지갑 소유자의 서명 주소가 계정 주소와 다른 일반 컨트랙트 지갑은 이 서명 흐름의 지원 대상에 포함하지 않습니다.
6. 사장님 계정으로 **확정하고 보관하기**를 누릅니다. `confirmAndLock`을 먼저 시뮬레이션하고, 전송·확인 후 실제 `lockedWages(recordId)`를 다시 조회합니다.
7. 기록 JSON을 내보냅니다. 서명을 제외한 원본의 SHA-256, EIP-712 record ID, 지급 조건과 두 서명이 포함됩니다. 파일을 다시 불러와 **파일과 체인 대조하기**를 누르면 `WageLocked` 이벤트의 지문과 비교합니다.
8. 급여일 뒤 지갑으로 `release(recordId)`를 실행하거나 아래 자동 실행기를 사용합니다. 지급 시각은 체인 시간을 기준으로 판단하고 돈은 기록의 알바생 지갑으로만 갑니다.

보관한 뒤에는 지급 시각을 바꿀 수 없습니다. 보관 전 조건을 고치려면 **서명 지우고 다시 준비하기**로 양쪽 서명을 지웁니다. 전송한 거래 해시는 즉시 저장하며, 결과를 모르면 새 전송을 막습니다. 새로고침 후 **미확인 거래 다시 확인하기**로 결과를 조회합니다. 보관 확정 기록은 JSON으로 다시 내보낼 수 있습니다.

`chain-config.ts`는 배포 주소와 ABI, `work-record.ts`는 원본·서명·JSON 형식, `sepolia-gateway.ts`는 실제 조회·거래·지문 검증, `chain-session.ts`는 로컬 준비 기록과 거래 해시를 맡습니다. 실제 모드 도메인은 `ChemU Daily Wage Escrow`, 버전 `1`, chain ID `11155111`, 검증 주소 `0x2342ef5F31BDa58Eb84F7f422Fd1ad7005fF4C19`입니다.

```text
WorkRecord(address employer,address employee,uint256 grossWage,uint64 payday,bytes32 workRecordHash,uint256 nonce)
```

`workRecordHash`는 서명 없는 canonical JSON의 SHA-256에 `0x`를 붙인 bytes32입니다. `recordId`는 해당 `WorkRecord`의 EIP-712 digest라 서로 다릅니다. 지급 호출에는 record ID를 사용합니다. 브라우저의 계약 동의는 서버 인증이나 법적 전자계약 기능이 아닙니다. 기기 간 원본·서명 공유 API는 아직 없으며 실제 모드도 한 브라우저에서 시연합니다.

## 급여일 자동 실행기 (Windows 지원)

기본값은 읽기 전용입니다. 아래는 이미 지급된 전달 기록을 조회하는 예입니다.

```powershell
npm.cmd run release:watch -- --record 0x4da2a43c54d5ec9f5eaa7c596e0dc87e850cf1eecfd98c3551b2698619b92efc --once
```

실제 자동 지급은 **새로 보관한 record ID**를 넣고 `--send`를 명시해야 합니다. 실행기 계정의 `RELAYER_PRIVATE_KEY`를 해당 프로세스 환경변수에 설정하고 Sepolia ETH를 준비합니다. 키를 브라우저 입력이나 `NEXT_PUBLIC_` 변수에 넣지 않습니다. 프로그램은 `.env`의 배포자 키를 자동으로 읽지 않습니다.

```text
npm.cmd run release:watch -- --record YOUR_RECORD_ID --send
```

`--record`를 여러 번 지정하면 여러 건을 감시합니다. 10초마다 체인 시간을 확인하고, 이미 지급된 건은 건너뜁니다. 전송 중 오류가 나면 자동 재전송하지 않고 종료하므로 마지막 거래를 확인한 뒤 다시 실행합니다. `--send` 없이 실행하면 시각이 돼도 지급하지 않습니다. 발표 중 이 프로세스를 켜 두어야 하며 브라우저 페이지 자체는 자동으로 실제 거래를 보내지 않습니다.

## 검증

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
npm.cmd run evidence:verify
npm.cmd run evidence:verify -- --live
```

2026년 11월 28일 공유 준비에서 단위 테스트 **29개**, 브라우저 시나리오 **9개**(목모드 5개 + Sepolia 4개), TypeScript와 프로덕션 빌드가 통과했습니다. 실제 거래 경로의 브라우저 자동 테스트는 테스트 RPC를 사용하며, 기존 승인 중복 방지·새로고침 복원·ERC-1271 거부와 승인·계정 전환 뒤 서명을 확인합니다. 설치된 Microsoft Edge를 사용하며 다른 브라우저는 `playwright.config.ts`의 채널을 조정합니다. Windows 외 환경에서는 `npm.cmd` 대신 `npm`을 사용합니다.

사용자는 실제 MetaMask에서 수동 지급과 CLI 자동 지급을 완료했습니다. 자동 실행기는 1,176초 전부터 대기했고 2026-11-28 02:30:00 KST 예정 기록을 **02:30:12 KST** 블록에서 92,880 KRWt 지급했습니다. 개발 도구는 실제 거래를 보내지 않고 성공 영수증·이벤트·지급 상태를 읽기 전용으로 확인했습니다.

`chemu-sepolia-0.json`과 `chemu-sepolia-3.json`은 별도 기록이며 원본·양측 서명·실제 보관 이벤트 대조를 각각 통과했습니다. 파일 검증은 그 파일의 record ID를 기준으로 하므로 과거 정상 파일도 통과합니다. 현재 조회한 기록 또는 최신 기록과 같은지 확인하려면 record ID와 nonce를 별도로 비교합니다.

재현 가능한 JSON·실행 로그·거래 링크·실제 조회 캡처와 검사 로그는 [검증 증빙](../docs/demo-evidence/2026-11-28/README.md)에 모았습니다. 공개 기록만 검사하는 `evidence:verify`는 기본 오프라인이며 `--live`를 붙이면 실제 Sepolia에 읽기 전용으로 질의합니다. CLI의 RPC 변경은 프로세스 환경변수로 지정하며 Next.js의 `.env.local`을 자동 로드하지 않습니다. 캡처를 다시 만들려면 로컬 앱을 켜고 `node scripts/capture-evidence.mjs`를 실행합니다. 이 명령도 연결된 지갑 없이 과거 기록만 조회합니다.

코드 리뷰 포인트, 알려진 제한, 팀원 설치와 발표 준비는 [개발 전달 안내](../docs/handoff/README.md)를 확인합니다.
